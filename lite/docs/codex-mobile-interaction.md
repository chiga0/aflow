# Codex 移动端交互调研（2026-05）

> 调研目的：aflow-lite 移动优先 UI（`web/src/chat-ui.tsx`）的交互参照系。
> 来源：apidog.com《How to Use OpenAI Codex from Your Phone》、ofox.ai《Codex Mobile App》（均为 2026-05 发布后实测文章），结合 OpenAI 官方口径 "Work with Codex from anywhere"。

## 1. 产品定位：控制面，不是编辑器

Codex Mobile（内嵌于 ChatGPT App，2026-05-14 全量 preview，含 Free）的一句话定位：

> "Mobile is not an editor; it is a **control surface** for a remote agent."

手机端做的事（官方口径）：

- 跨所有 thread 查看进度（**read**）
- 审阅产出：diff、测试结果、截图、终端输出（**review**）
- 批准/拒绝敏感命令（**approve**）
- 新建任务、附加上下文（截图/粘贴的 bug 报告）、切换模型（**start & steer**）

不做的事：写代码、长 diff 精读（>80 行体验差，官方建议回桌面）。

**对 aflow-lite 的启示**：lite 的定位与此完全一致（手机发起/监督，VPS 执行）。UI 的信息架构应该围绕"任务状态 + 审批 + 摘要阅读"，而不是"聊天 + 代码"。

## 2. 关键交互模式清单

| # | 模式 | Codex 实现 | 交互价值 |
|---|------|-----------|---------|
| 1 | **任务列表是首屏** | 底部导航进 Codex tab，活跃任务/线程列表，带实时状态 | 一眼看到"什么在跑、什么等我"，而非空白聊天框 |
| 2 | **审批卡片 + 锁屏通知** | 遇到迁移/删文件/生产配置等命令，推送可操作卡片，锁屏可直接批准/拒绝 | agent 类产品的核心时刻：人不被拴在桌前，agent 不卡在权限上 |
| 3 | **实时多模态流** | 截图、终端输出、diff、测试结果、审批请求实时流入 | 过程可见 = 信任感 |
| 4 | **摘要优先阅读** | 手机上读 summary，长 diff 留给桌面 | 承认手机屏幕的物理限制，不强求完整审阅 |
| 5 | **截图作为任务输入** | 新线程可直接附图（截图/Slack 粘贴的 bug） | 手机上"描述问题"最低成本的方式 |
| 6 | **任务中途换模型** | 发现任务比预想难，把线程从便宜模型升到最强模型 | 成本/能力的动态权衡 |
| 7 | **断线不丢状态** | 任务在云端继续跑，重连后状态刷新；审批掉线不阻塞任务 | 移动网络是常态，不能假设长连接稳定 |
| 8 | **QR 配对** | Mac 出 QR，手机扫码即完成配对，无账号/key 步骤 | 首次体验决定习惯是否养成 |
| 9 | **语音输入** | 复用 ChatGPT 语音模式 | 长文字输入是手机短板，语音兜底 |
| 10 | **跨设备同一会话** | 桌面/手机双向同步，多并发会话 | "监督席"从椅子转移到口袋 |

## 3. 已验证的真实使用场景（ofox 两周实测）

手机端好用：
- 批准 agent 准备好但不敢自己跑的迁移
- 读测试失败报告，让 agent 换个修法
- 盯长构建/测试，不用开着笔记本
- 从截图/粘贴的 bug 报告直接开新任务
- 任务中途升级模型

手机端不行：
- 一次读 >80 行 diff（pinch-zoom 可用但不愉快）
- 输入超过一段话的澄清（语音只解决一半）

## 4. 架构要点（与 aflow-lite 的对照）

- Codex worker 跑在别处（Mac），手机只是窗口；权限与凭据留在宿主机 → aflow-lite 同构（pi 跑在 VPS，手机经 runtime 代理）
- relay 架构：低延迟持久连接是体验前提，弱网下"approve→等9秒→看结果"是已知痛点 → 我们的 SSE + replay buffer（Last-Event-ID 续传）是对的方向，审批动作要做成**幂等的 HTTP POST**，不依赖长连接
- 宿主休眠 = 手机只能看最后状态 → VPS 部署天然规避（永不休眠）

## 5. 对 aflow-lite UI 的落地清单（按优先级）

| 优先级 | 项 | 现状 | 动作 |
|---|---|---|---|
| P0 | 会话列表带状态徽标（running / 等待输入 / 完成 / 失败） | 只有时间 | 后端 list 增加 last_status；前端徽标 |
| P0 | 长消息折叠 + "展开" | 全文渲染 | 前端，>N 行折叠 |
| P1 | 图片附加到任务（截图输入） | 无 | /messages 接受 images；pi RPC 原生支持 image 输入 |
| P1 | 审批卡片（pi 权限事件 → 卡片 → 批准/拒绝） | pi headless 目前自动放行 | 需 pi RPC 审批协议支持，后续 Phase |
| P1 | 任务完成/需审批的推送通知 | 无 | PWA Notification API（自托管 VAPID） |
| P2 | 模型切换器 | 固定 env 模型 | models.json 多模型 + 会话级选择 |
| P2 | 语音输入 | 无 | 先用系统键盘听写兜底，不重复造 |

## 6. 明确不做的

- 手机上做 diff 精读 / 代码编辑（Codex 都不做）
- 自建语音识别
- 桌面端复杂布局（移动优先，桌面能用即可）
